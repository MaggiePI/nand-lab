Using the lab
Pick an example from the toolbar or write your own. Hit Assemble & reset to compile and load it into memory.
Clock advances one phase (fetch → operand → execute — three clocks per instruction). Instruction runs one complete instruction. Run runs continuously; hit it again to pause and inspect state.
Switch to the Lab tab to write code and watch the datapath. The CPU datapath highlights whichever component is active each phase. Registers, flags (Z, C, V), and the program counter update live. The Output, Memory, and Trace panels are in the right column.
The tools below show the building blocks: every gate and every adder step derives from NAND alone.

Meet N8
N8 is a minimal 8-bit computer designed to be transparent. Four 8-bit registers (R0–R3). A 4-bit opcode. Two bytes per instruction. A unified 256-byte address space — program, I/O, and pixel memory all share it.
ADD / SUB / CMP update Z (zero), C (carry or no borrow), and V (signed overflow). Logical operations (AND, OR, XOR, NOT, SHL) clear C and V. Loads and branches preserve flags.
Program bytes occupy addresses 00–BF. Writing to C0–CF drives the 16×8 pixel framebuffer. ST to F0 prints a character to the terminal output; LD from F1 consumes the next queued input byte.
The ALU and register input multiplexers use real NAND-derived Boolean gates implemented in JavaScript — each gate call counts. Memory and sequential state (registers, flags, PC) are host-language objects, not simulated flip-flops. The datapath diagram shows architectural data flow, not electrical timing.
Limitations. No interrupt system, no stack, no hardware multiply or divide. No signed arithmetic beyond flag reporting. The address space is flat and small by design. This is a teaching model, not a production ISA.
